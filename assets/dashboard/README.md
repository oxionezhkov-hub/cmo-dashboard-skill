# Дашборд отдела маркетинга

Светлый интерактивный дашборд со сквозной аналитикой: видно, сколько потратили в каждом кабинете,
сколько заявок и продаж это дало, где рвётся воронка и что с этим делать.

Источники: Яндекс.Директ, VK Ads, Telegram Ads, Яндекс.Метрика (включая поведение на страницах),
коллтрекинг, amoCRM, Telegram-бот, Google Sheets. Выводы считает связка «правила + Claude»,
на странице есть блок вопросов к ИИ по текущим цифрам.

Страница открывается двойным кликом по `index.html` — без сервера и без интернета.

```
dashboard/
  index.html                вёрстка
  app.js                    отрисовка: период, фильтры, попапы, запросы к ИИ
  vendor/                   Chart.js локально, чтобы страница работала офлайн
  data/
    dashboard.json          единая модель — результат сборки
    dashboard.js            та же модель как window.DASHBOARD_DATA (для открытия по file://)
  collectors/
    collect.js              оркестратор: собрать → свести → посчитать выводы → записать
    normalize.js            приведение девяти выгрузок к одной модели
    insights.js             выводы: правила + Claude API, текст дайджеста
    yandex_direct.js        Reports API v5
    vk_ads.js               API статистики VK Ads
    telegram_ads.js         выгрузка кабинета из листа таблицы
    yandex_metrika.js       Reporting API + поведение на страницах
    calltouch.js            журнал звонков коллтрекинга
    amocrm.js               API v4
    telegram_bot.js         события бота + Bot API
    google_sheets.js        план и расходы вне кабинетов
    demo_source.js          генератор данных для показа без доступов
    config.example.json     шаблон конфига
  build-worker-assets.mjs   сборка страницы в модуль для Cloudflare Worker
  automation/               обновление по расписанию: GitHub Actions и cron воркера
```

## Быстрый старт

```bash
cd dashboard/collectors
node collect.js                  # соберёт данные за последние 28 дней
open ../index.html               # или просто открыть файл в браузере
```

Нужен только Node 18+ (встроенный `fetch`), зависимостей нет. Без `config.json` данные для показа
генерирует `demo_source.js` — в том же формате, в котором их отдают реальные API.

## Боевой режим

1. `cp config.example.json config.json`, заполнить доступы. Значения вида `"env:AMO_TOKEN"`
   подставляются из переменных окружения — токены в репозиторий не попадают, `config.json` в `.gitignore`.
2. Проверять по одному источнику: выключите в конфиге всё, кроме проверяемого.
3. Запустить:

```bash
DIRECT_TOKEN=... VK_ADS_TOKEN=... METRIKA_TOKEN=... AMO_TOKEN=... CALLTOUCH_TOKEN=... SHEETS_API_KEY=... \
ANTHROPIC_API_KEY=... node collect.js --mode=live --ai
```

Флаги: `--mode=live|demo`, `--ai` (выводы через Claude), `--notify` (дайджест в Telegram),
`--from=YYYY-MM-DD --to=YYYY-MM-DD`, `--days=28`.

Где взять каждый токен и куда его вставить — в скилле, файл `references/secrets.md`.

Если источник отвалился, сборка не падает: он помечается статусом `error`, остальные блоки считаются,
а в разделе «Откуда берутся данные» видно, чего не хватает.

## Что на странице

- **Итоги периода** — восемь показателей с планом и сравнением с прошлым периодом.
- **ИИ-аналитика** — выводы с цифрами, действием и оценкой эффекта, плюс блок «Уточнить у ИИ».
- **Динамика** — заявки, расход и CPL по дням, сквозная воронка от показа до продажи.
- **Каналы и кампании** — расход против выручки, CPL, ROMI, все кабинеты в одной таблице.
- **Сайт и страницы** — источники визитов и поведение: прокрутка, клики, формы, клики впустую.
- **Звонки** — коллтрекинг по часам и дням недели, доля пропущенных.
- **Telegram-бот** — конверсия в квиз и записи на консультацию.
- **Продажи** — менеджеры, этапы воронки, причины отказов.
- **План и факт** — выполнение и прогноз на месяц, дайджест руководителю.

Переключатель периода в шапке (7 / 14 / 28 дней) пересчитывает всё, что имеет дневную разбивку.
Кнопка «Подробнее» в каждом разделе открывает попап с фильтрами, сортировками и детальными таблицами.
Кнопка «Обновить» перечитывает данные без перезагрузки страницы.

## Публикация на Cloudflare Worker

```bash
node dashboard/build-worker-assets.mjs   # собирает dashboard/dist/worker-assets.js
wrangler deploy
```

Маршруты воркера: `/dashboard` — страница, `/dashboard/app.js` — скрипт, `/dashboard/data.json` — модель
(из KV `dashboard:latest`, если она там есть), `/api/dashboard/ask` — вопросы к ИИ.
Секреты: `wrangler secret put CLAUDE_API`, при необходимости `DASHBOARD_AI_MODEL`
(по умолчанию `claude-haiku-4-5-20251001`).

Другие варианты хостинга: GitHub Pages, Cloudflare Pages, любой статический сервер — папка самодостаточна.

## Выводы

Считаются в два слоя:

1. **Правила** (`insights.js`) находят аномалии и считают цифры: кампании с высоким CPL и слабой квалификацией,
   обвал конверсии в воронке бота, пропущенные звонки, медленных менеджеров, отставание от плана,
   лучший канал по ROMI, страницы с кликами впустую. Работают всегда — без ключей и интернета.
2. **Claude** получает данные и найденные правилами аномалии и формулирует выводы для руководителя.
   Модель не считает — она объясняет и приоритизирует. Модель по умолчанию — Haiku, меняется в конфиге.

## Автообновление и уведомления

- `automation/github-actions.yml` — ежедневная пересборка и коммит свежих данных.
- `automation/cron-worker.md` — то же на cron-триггере воркера.
- Дайджест уходит в Telegram при `--notify`; при `notify.onlyIfCritical: true` — только когда есть
  критичный вывод, чтобы руководителю не приходило «всё хорошо» каждый день.
