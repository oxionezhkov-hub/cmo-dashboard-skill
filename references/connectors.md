# Фаза 1. Доступы и коннекторы

Порядок один: получить доступ → проверить одним запросом → включить в конфиг.
Не переходите к следующему источнику, пока предыдущий не отдал реальные строки.

## Яндекс.Директ — Reports API v5

- Токен: OAuth-приложение с правом доступа к Директу (oauth.yandex.ru). Агентству дополнительно нужен заголовок `Client-Login`.
- Отчёт: `CAMPAIGN_PERFORMANCE_REPORT`, поля `Date, CampaignId, CampaignName, Impressions, Clicks, Cost`.
- Формат ответа — TSV, не JSON. Заголовки отчёта отключаются `skipReportHeader`/`skipColumnHeader`/`skipReportSummary`.
- Ответ 201/202 означает «отчёт в очереди»: повторить запрос через `retryIn` секунд. Это не ошибка.
- `returnMoneyInMicros: false` — иначе расход приедет умноженным на миллион.
- `IncludeVAT: YES/NO` — главная причина расхождений с интерфейсом. Выберите один раз и зафиксируйте в брифе.

## Яндекс.Метрика — Reporting API

- Тот же OAuth-токен, если в приложении отмечены права Метрики.
- `metrics=ym:s:visits,ym:s:bounceRate,ym:s:pageDepth,ym:s:goal<ID>reaches`, `dimensions=ym:s:date,ym:s:lastsignTrafficSource`.
- `goalId` — из «Настройка → Цели». Без него дашборд покажет визиты, но не конверсию источника.
- Метрика отдаёт визиты, CRM — заявки. Цифры не совпадут, и это нормально: считать конверсию
  нужно последовательно внутри одного источника, а не делить заявки CRM на визиты Метрики.

## VK Ads — API статистики

- Токен: ads.vk.com → Настройки → Доступ по API.
- Статистика знает только id кампаний, названия приходят отдельным запросом `campaigns.json` — коннектор их склеивает.
- Дневная разбивка: `statistics/campaigns/day.json` с `date_from`/`date_to`.

## Telegram Ads

Публичного API статистики у кабинета нет. Рабочие варианты: выгрузка из кабинета в лист таблицы
(коннектор читает его тем же Sheets API и отдаёт строки в формате рекламных кабинетов) или данные
реселлера, если закупка идёт через агентство с API. Договоритесь с клиентом, кто и когда обновляет лист:
это единственный источник в связке, который зависит от человека.

## Коллтрекинг

- Calltouch: журнал звонков `calls-diary/calls` с `clientApiId`, даты в формате ДД/ММ/ГГГГ.
- Roistat, CoMagic, UIS отдают то же самое другими полями — переписывается только разбор ответа,
  контракт коннектора не меняется: плоский список звонков с датой, часом, источником, признаками «принят» и «целевой».
- Источник звонка сводится к каналам модели функцией `mapSource` — её надо подогнать под разметку клиента.

## Поведение на страницах (Метрика + Вебвизор)

Просмотры и время на странице Метрика отдаёт сама. Прокрутка, клики по CTA, старт и отправка формы —
это цели и события, которые нужно один раз настроить в счётчике; их id прописываются в `metrika.pageGoals`.
Рейдж-клики Метрика в API не отдаёт: они видны в Вебвизоре, поэтому в модель попадают через
специально настроенное событие «клик по некликабельному» либо остаются нулём.
Если у клиента этих целей нет — это первая задача по аналитике, без них раздел про поведение будет пустым.

## Telegram-бот

В Bot API нет аналитики воронки — её отдаёт сам бот. Нужен эндпоинт вида
`GET /api/bot-events?from=&to=` → `[{date, joined, left, started, quizCompleted, bookedCall}]`.
Если бот ещё не пишет события — это первая задача: логировать шаги в KV/БД по дате.
Размер канала берётся из Bot API (`getChatMemberCount`).

## amoCRM — API v4

- Долгоживущий токен интеграции (Интеграции → Создать интеграцию → вкладка «Ключи и доступы»).
- `GET /api/v4/leads?filter[created_at][from]=<unix>&filter[created_at][to]=<unix>&limit=250&page=N`, листать до пустого ответа (204).
- Названия этапов приходят отдельным запросом `/leads/pipelines`, ответственные — `/users`.
- Канал, кампания, квалификация и причина отказа живут в кастомных полях: их id прописываются в `fieldMap`.
  Узнать id: `GET /api/v4/leads/custom_fields`.
- Ограничение — 7 запросов в секунду. Коллектор идёт последовательно, этого достаточно.

## Google Sheets — API v4

- Простой путь: доступ «по ссылке» + API-ключ, читаем `values/<Лист>!A1:B20`.
- Строгий путь: сервисный аккаунт, таблица расшарена на его почту, в конфиг кладём access token.
- Таблица — единственный источник, который ведут руками, поэтому: два столбца, никаких объединённых ячеек,
  числа без пробелов и знака рубля (коллектор всё равно чистит строку, но лучше не проверять это на проде).

## Добавить свой источник

1. Новый файл `collectors/<source>.js` с функцией `fetch<Source>(config, period)`, возвращающей плоские строки.
2. Строка в `collectLive()` внутри `collect.js` — с оборачиванием в `tryFetch`, чтобы падение не роняло сборку.
3. Секция в `config.example.json` с токенами через `env:`.
4. Обработка в `normalize.js` и, если нужен новый блок, — в `app.js`.

## Проверка одного источника

Выключите в `config.json` все источники, кроме проверяемого, и запустите `node collect.js --mode=live`.
В логе будет видно `Источник: ok, N строк за M мс` либо текст ошибки от API — с ним и идите разбираться.
